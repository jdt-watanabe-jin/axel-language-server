# Workspace symbols

`workspace/symbol` searches unopened and open AXEL files throughout the initialized workspace folders. Files with `.axl`, `.h` and `.hh` extensions are included case-insensitively. With no folders, only open AXEL file documents are searched. External includes and libraries outside the workspace are not candidates. Symbol search does not extend the scope of references, completion or diagnostics.

Types, functions, methods, constructors, operators, global variables, fields, enum members, source macros, GUI parts and event handlers are included. Parameters, function-local declarations, include directives and declarations generated by macro expansion are excluded. Distinct declarations, definitions and overloads remain separate navigation targets. Results contain the physical name range; signatures are not guaranteed in the client UI.

Queries match names and qualified names without case sensitivity. The server ranks exact, prefix, substring, then ordered-subsequence matches; clients may reorder results. `Version::make` searches qualified names and `mkv` matches `makeVersion`. Empty or whitespace-only queries return all candidates without a silent result limit.

## Exclusions

Send this configuration in initialization options and `workspace/didChangeConfiguration.settings`:

```json
{
  "workspaceSymbols": {
    "exclude": ["**/generated/**"]
  }
}
```

The default is an empty array. `.git` directories are always excluded; `node_modules` is not special. Patterns apply relative to each workspace root, including open files and descendants of excluded directories. With no roots, the document's parent is the base. `*` matches within one path segment, `?` matches one character, and `**` matches zero or more segments. Use `/` separators. Absolute paths, `..` segments and negative patterns are invalid and logged. Missing or non-array settings use the default; invalid elements are ignored. Reconfiguration replaces the array.

Editor file/search exclusions and `.gitignore` do not implicitly restrict symbol searches. Symlinks and junctions below workspace roots are not traversed. Only `file:` documents are supported.

## Conditions and indexing

Source extraction uses the configured tool, target platform, internal features and defines, plus local preprocessing. Definitely inactive branches are excluded; uncertain branches, including unknown include-dependent conditions, remain searchable. The last include context or the order in which files were opened does not change the result. This search does not enumerate all include-context combinations or load external libraries to resolve every condition.

The index builds in the background. Searches wait for a complete updated snapshot and support cancellation; cancelling a search does not cancel shared indexing. Work-done progress is reported when the client supports it and supplies a token. Editing and other document requests can continue while indexing runs. Unchanged files reuse extracted entries, and later searches reconcile filesystem metadata to recover missed watcher events.

Unsaved text takes precedence over disk contents. Closing a document restores its disk content, or removes it in a folderless workspace. A deleted file whose document remains open stays searchable until the document closes. Closing an editor tab does not necessarily close the document in every client. File events, folder changes and configuration changes update the index without restarting. An edit during result matching rejects the stale result with `ContentModified`.

Unreadable files are logged and skipped without keeping their old entries. Recoverable declarations in syntactically invalid files remain searchable. Indexing alone does not publish diagnostics for unopened files. `workspaceSymbol/resolve` and partial results are not provided; locations are complete in the search response.
